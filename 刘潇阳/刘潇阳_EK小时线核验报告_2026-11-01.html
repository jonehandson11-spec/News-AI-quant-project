三、口径与发现

3.1 系统显示的是「bar 结束时刻」，Yahoo 原始数据是「bar 开始时刻」。
系统显示 2026-10-28 10:30，对应 09:30–10:30。拿 Yahoo 原始数据核对必须 +1 小时，否则会误判成“时间整体错一小时”。本次 10/10 按结束时刻对齐，无一错位。
3.2 港股每交易日 7 根 bar，比东方财富多一根。
系统存 09:30 / 10:30 / 11:30 / 12:30 / 13:30 / 14:30 / 15:30 起算的 7 根；东财 6 根（跳过 11:30–12:00 这 30 分钟）。按显示时刻对齐后 6 根全部吻合。午休输入返回 12:00 那根并标 lunch_break。
3.3 美股尾盘收盘价存在集合竞价口径差。
XOM 最后一根 bar（15:30–16:00 ET）系统 182.06、东财日收盘 182.02，差 0.04（0.02%）；港股 16:00 那根与东财完全一致。
3.4 BZ=F 是未做换月调整的连续合约，换月日会出现价格台阶。
相邻两根小时 bar 跳变超过 3 美元的有 79 次。典型：2026-04-07 当天 15:00 收 111.49 → 18:00 那根掉到 94.06 并收 95.0，之后一直维持 94–96——不是暴跌，是换月台阶；同日东财当月连续收 103.42，差 8.72 纯属换月时点不同。
影响：新闻若落在换月日附近，会算出 ±10% 的假涨跌。日级收盘价也因此不能用外部日线核对，只能逐小时比同一时间戳。

四、发现的缺陷与处理

4.1 Windows 下页面打不开（已修复）

现象：直接打开 http://127.0.0.1:8765/，下拉框只有 7 个静态默认标的（比亚迪/腾讯/阿里/中芯/汇丰/盈富/3033），0883 / 0857 / 0386 / XOM / BZ=F 一个都选不到；点「自动取价并查询」无反应；底部状态停在「检查服务中…」。
证据（数据侧）： 
GET /app.mjs → HTTP/1.0 200 OK
Content-type: text/plain          ← 应为 text/javascript
控制台：Failed to load module script: Expected a JavaScript-or-Wasm module script
        but the server responded with a MIME type of "text/plain".
根因：web/server.py 用标准库 SimpleHTTPRequestHandler，未注册 .mjs；Windows 注册表缺省映射成 text/plain，浏览器按 ES Module 规范拒绝执行，整个前端脚本不运行。Linux/macOS 正常，仅 Windows 中招。
修复：Handler 上显式覆盖 extensions_map（.mjs/.js → text/javascript），并在模块导入时 mimetypes.add_type 兜底；补 HTTP 测试断言响应头。提交 4962330。

4.2 半日市缺最后一根 bar（已接入检测与标记）

判据：正常交易日小时线应覆盖到收盘；少于即缺口。清单见 刘潇阳_小时线缺口清单_2026-11-01.csv。

处理思路：不伪造数据，但不许它悄悄给出错误收盘价。
① 新增 news_price_query/hourly_quality.py：按交易所日历逐日核对「最后一根 bar 的结束时间 vs 当日收盘时间」。不按固定根数判断——Yahoo 港股 7 根、东财 6 根，网格不同会误判；比收盘时间对所有市场都成立。固定月份合约默认跳过（Yahoo 本身稀疏）。
② 新增 CLI 体检：python -m news_price_query quality --db … --fail-on-gaps，真实库跑出 4447 个交易日中 49 天覆盖不全，可直接接 CI。
③ 查询侧：当日已收盘、但最后一根 bar 未覆盖到收盘时，基准价 flag = incomplete_session，页面提示「这个价格不是当日收盘价」；新闻在收盘前不会误报。
提交 4962330。
实例（数据侧，可直接复跑）：0883.HK 2024-12-24 14:00 查询 → baseline 2024-12-24 11:30、价 18.72、flag incomplete_session；官方收盘 18.60。同一天 10:00 查询不误报（当天还没收盘）。

六、没做到的部分（如实说明）

  • 没有用 Yahoo Finance 本身做对照。Yahoo 对中国大陆 IP 全域停服（返回官方停服页），本机 IP 还被单独 403 限流。按「雅虎打不开就换渠道」的授权改用东方财富 / 雪球——两边不同源，同时验证了管道和供应商，但严格的“Yahoo 同源”这一步没做。
  • 2024-11 ~ 2025-10 的逐小时外部对照没做成。东财小时线只回溯约 1 个月、雪球约 3.5 个月，腾讯/新浪/investing 被拦、富途 OpenD 未装、纳斯达克只返日线。该段用第二节的日线级整日审计兜住：能发现错日、错价、缺口，发现不了“单根小时线被替换”。
  • 缺 bar 的数据本身没有补。不伪造行情：半日市的最后一根目前是标记而不是补齐，需要等能取到该 bar 的数据源后重抓。
  • 组员共享实例没验成，不是网络问题。README 里的 bookmarks-…trycloudflare.com 这次 DNS 直接 NXDOMAIN，隧道已失效，需组长重开。

七、建议的下一步

  • CI 接入体检：在价格更新后跑 quality --fail-on-gaps，让缺口在合并前就暴露。
  • 补抓 3 个异常缺口日：2026-01-30、2026-02-02、2026-04-20。
  • 半日市修复：抓取端在 half_day 的 session close 之前多留一根 30 分钟 bar；在补上之前，incomplete_session 保证不会静默出错。
  • 布伦特换月：换月日加显式标记，避免 ±10% 假涨跌；参考 continuous_crosses_roll 在日线模式里已有实现，可移植到小时模式。
