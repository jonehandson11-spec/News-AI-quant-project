# 本地价格库（日线与小时线）

查询网页默认从本地 SQLite 价格库取小时线；命令行默认窗口为交易小时：不用导入 CSV，也不用登录富途 OpenD。富途和 CSV 仍可作备选。

- 代码：`news_price_query/price_store.py`（库和 `LocalDbPriceProvider`）、`news_price_query/price_update.py`（增量更新）、`scripts/update_prices.py`（命令）
- 库文件位置：默认 `~/.news_price_query/prices.sqlite3`；可用环境变量 `NEWS_PRICE_DB` 或 `--db` 改。库文件**不进仓库**（已加 .gitignore）
- 数据源：yfinance 日线，仅限内部研究，不对外发布或再分发
- `hourly_prices` 独立保存 yfinance 原始 1 小时 OHLCV（含可选 Adj Close），日线仍在 `daily_prices`；时间同时保存 UTC 和交易所当地时区
- 支持港股、美股、加拿大、沙特股票和四条 NYMEX 期货连续合约；表里有 `market`、`currency` 字段，日历按 market 选取

## 安装与更新

```sh
pip install yfinance            # 只有更新脚本需要；查询本身只用标准库
python scripts/update_prices.py --universe news_price_query/data/universe_example_hk.csv
python scripts/update_prices.py --universe news_price_query/data/universe_example_hk.csv --hourly-only
python scripts/update_prices.py --universe news_price_query/data/universe_example_hk.csv --no-hourly
python scripts/update_prices.py --universe /path/to/your_pool.csv --universe news_price_query/data/universe_example_hk.csv
python scripts/update_prices.py --universe /path/to/your_pool.csv --refetch 2222.SR --start 2000-01-01
```

- 股票池 CSV 需要有 `ticker`、`yfinance代码` 或 `代码`（如 00883）列；`中文名`、`英文名`、`常用别名`（用 ; 分隔）会被读入，用于网页别名和新闻匹配。仓库只放了只含代码的示例池；团队股票池文件不要提交。
- 盈富基金 2800.HK 和恒生指数 ^HSI 总是一起更新（作为对照）。
- 增量：已有的代码只从最后一个已存交易日往前 `--overlap-days`（默认 10）个交易日开始重拉，用来接住数据修正。若重叠区间里 复权价/收盘价 的比例变了（新的分红或拆股会改变整段复权历史），就自动整段重拉该代码。
- 交易日历修正后，用可重复的 `--refetch TICKER` 指定代码：先清除其已存日线和期货换月记录，再从 `--start` 全量下载，使旧历史按新日历重新过滤。
- 非交易日的行（yfinance 的假日填充行）按**交易日历**丢弃，不按成交量为 0 删除：半日市成交量常为 0，但价格是真的。
- 当天（交易所当地日期）的行不入库，因为可能未定稿；下次运行再写入。
- 每次运行记一条 `update_runs`（run_id、开始/结束时间、状态、行数），每行价格记 `source`、`fetched_at`、`run_id`；查询结果带 `data_version`。
- 输出会列出每个代码：已存行数、日历交易日数、缺失交易日（日历有、数据源没有）、丢弃的非交易日行数。
- 默认同时更新日线和 1 小时线；`--no-hourly` 只更新日线，`--hourly-only` 只更新小时线。小时线首次回补约 729 天，之后从最后一根已存 bar 往前重拉 5 天并幂等覆盖；未结束的 bar 不入库。输出和 `--json` 会分别列出每个代码的小时线写入数、库存行数、覆盖时间范围和错误。小时线全体失败时状态为 `partial`，个别失败不会中断其他代码或日线更新。

### 每天自动更新

脚本可直接被定时任务调用（退出码 0 = 全部成功，1 = 部分失败）。建议在香港收盘后、次日开盘前运行，例如每天 HKT 20:00 之后或 Paris 时间早上：

```sh
cd /path/to/News-AI-quant-project && python scripts/update_prices.py --universe /path/to/pool.csv
```

## 查询

```sh
python -m web.server            # 默认：本地价格库 + 交易小时窗口，仅 127.0.0.1:8765
python -m web.server --provider futu --mode minute   # 旧版：富途 OpenD + 分钟窗口
python -m news_price_query query --asset 0883.HK --time 2026-09-28T11:17:42+08:00 --provider local --mode daily
```

结果每个窗口给出：原始涨跌幅（`return_pct`，收盘价仅拆股调整）、复权涨跌幅（`adj_return_pct`，含分红）、相对 2800.HK 和 ^HSI 的超额收益（原始和复权两套，`excess_return_pct` / `adj_excess_return_pct`，简单差值）、状态和来源。

状态与标记：
- `status`：`on_date`、`deferred`（目标日无行情，往后顺延，最多 5 个交易日）、`deferred_back`、`pending`（未到期）、`missing`。缺失从不当作 0。
- `flag`：`missing_data` = 目标交易日该股没有行情行（停牌或数据缺失，免费数据分不清，如实标缺数据）；`zero_volume` = 非半日市的交易日成交量为 0（零成交，或数据源没给成交量）。指数不打 `zero_volume`。
- 期货可保存有限的零价、负价收盘（如 2020-04-20 CL=F）；股票仍要求收盘价大于 0。日线窗口的基准价或窗口价 ≤ 0 时，相应收益率为 `null`，窗口标 `nonpositive_price`；已有的缺数据或零成交标记优先保留。原始价和复权价分别判断。

网页只在本机运行（默认监听 127.0.0.1）。是否在内网或公网共享须 Ek 批准，并先加访问控制。

## Multi-market oil research pool (block 3)

`news_price_query/data/research_assets.csv` registers Ek's first-phase oil research
targets (19) plus same-market benchmarks: research stage (研究环节), market (MIC),
exchange, currency, price unit, asset type, data ticker, Chinese/English aliases, exclude terms
(e.g. 「中海油」 never matches 「中海油田服务」/2883.HK) and data status.
`news_price_query/data/universe_oil_research.csv` is the code-only pool (ticker, stage).

Daily update (same command for the routine; run once a day, any time):

    python scripts/update_prices.py --universe news_price_query/data/universe_oil_research.csv

(needs `pip install yfinance`; `pandas_market_calendars` is only needed to rebuild
calendars with `python -m news_price_query.build_calendar XHKG XNYS XTSE XSAU NYMEX XLON`.)

Markets and calendars (`data/calendars/*.csv`, generated by pandas_market_calendars 5.5.0;
HK uses `data/hkex_calendar.csv` with weather overrides):

| Market | Calendar / time zone | Benchmarks | Currency |
|---|---|---|---|
| XHKG | HKEX, Asia/Hong_Kong | 2800.HK, ^HSI | HKD |
| XNYS (NYSE + Nasdaq PAA) | NYSE, America/New_York | SPY, XLE | USD |
| XTSE | TSX, America/Toronto | XIU.TO, ^GSPTSE | CAD |

- t0 and windows use the asset's own exchange calendar; news times are entered in HK
  time and converted (e.g. 2026-10-22 05:30 HKT = 2026-10-21 17:30 New York, after the

- Cross-market benchmarks are skipped (they would need FX and calendar alignment).
- XSAU overrides use the official [Saudi Exchange holiday calendar](https://www.saudiexchange.sa/wps/portal/saudiexchange/about-saudi-exchange/exchange-media-centre/saudi-exchange-holiday-calendar)

  see `data/calendars/XSAU_overrides.csv` for each date and its source note.

## Futures continuous series

`BZ=F`, `CL=F`, `RB=F`, and `HO=F` use Yahoo Finance daily continuous front-month
prices through the unchanged `update_prices.py --universe` command. NYMEX trade dates
are the intersection of `pandas_market_calendars` `CMEGlobex_CL` and XNYS sessions:
US holidays with only an early Globex halt have no settlement/Yahoo daily row. All
sessions use 09:00–14:30 ET; 14:30 is the NYMEX settlement time used for news timing.
The 2025-01-09 trading override is in `NYMEX_overrides.csv`.

`futures.py` derives last trade dates from CME/ICE contract rules. CL uses three NYMEX
business days before the business day on or before the prior month's 25th; HO and RB
use the prior month's last NYMEX business day. BZ uses the last London business day
of the second preceding month from March 2016; the older 15-day rule and transition
month are an assumption to verify against historical data. BZ=F is Yahoo's NYMEX
Brent Last Day Financial continuous series; final settlement follows ICE Brent, but
the ICE trading calendar is not used here. This is an approximation.

The continuous series is assumed to roll on the first NYMEX trade date after expiry.
The verified CLX26→CLZ26 example rolls on 2026-10-21. Roll dates are stored in
`futures_rolls` during updates and recomputed from the rules for reports, so any
price provider gets the same `crosses_roll` and `rolls` fields. Raw and adjusted
window observations also carry `adj_crosses_roll`/`adj_rolls`; non-futures windows
carry false and empty lists. A `跨换月` mark means the window return includes the
old/new contract price gap: **no roll adjustment** is applied.

Units: CL and BZ are USD/bbl, RB and HO are USD/gal, ICE low-sulphur gasoil is
USD/t. ICE gasoil has no free daily source and remains unavailable for queries.

### Roll-rule verification (2026-10-24)
- Per-contract Yahoo series: BZ=F, HO=F, RB=F equal BZZ26/HOX26/RBX26 from 2026-10-01 (not on 2026-09-30); CL=F equals CLZ26 from 2026-10-21 (not on 2026-10-20). All four match the rule.
- CL 2020: CLK20 last trade 2020-04-21 (CL=F -37.63 on 04-20 and 10.01 on 04-21 are the May contract); roll 2020-04-22.
- History (jump test): on the predicted roll day the absolute move is the largest of its 5-day neighbourhood in 29% (CL), 31% (HO), 42% (RB) of rolls vs 20% by chance; the day before/after are not elevated. For BZ the test is inconclusive (24% on the rule day, 30% one day later), so older Brent roll dates may be off by one day.

## Fixed-contract futures windows (block 5)
- Main result for BZ=F/CL=F/RB=F/HO=F = the single contract that was front month on the
  baseline day (e.g. BZX26), used for every before/after window. Windows ending after its
  last trade date are `expired` (合约已到期; no return, never zero). The continuous-series
  result stays as a reference (`windows[label].continuous`) with its 跨换月 marks.
- Single-contract prices are stored as tickers like `CLZ26.NYM` (market NYMEX, source
  `yfinance`). Each update fetches the current front and next contract. Yahoo lists only
  live contracts (e.g. CLZ26 from 2017-11-21, BZZ26 from 2018-11-01, HO/RB from 2022-11-30;
  expired contracts such as BZX26/CLX26 return nothing), so history accumulates only while
  a contract is live.
- For days the roll rule says contract C was front, the continuous price is C's price; those
  rows are stored for C with source `derived:<ticker> front-month` where no direct row exists
  (direct rows always win). Older months of an expired contract are missing (not invented).
- Near-expiry switch: let N = number of NYMEX trading days d with baseline_day < d <= the
  front contract's last trade date. If N < `min_days_to_expiry` (default 5,
  `daily_report.DEFAULT_MIN_DAYS_TO_EXPIRY`, overridable per call), the next contract is
  used and the result says 「临近到期，改用 XXX」 (`contract.switched`, `contract.note`,
  `contract.front_days_to_expiry`). Example: BZX26 on baseline 2026-09-29 has N = 1
  (only 09-30) -> BZZ26. CLX26 on baseline 2026-10-05 has N = 11 -> kept.


## 交易小时窗口

默认窗口是新闻前 6、3、1 个交易小时和新闻后 1、3、6 个交易小时。只累计日历开市时段，休市、午休、周末、节假日及天气停市均跳过。小时线约覆盖最近 729 天，超出覆盖范围的结果显示缺数据，不填零；`--mode daily` 保留原交易日窗口和日线更新。

Yahoo 港股小时线时间戳为 09:30、10:30、11:30、12:30、13:30、14:30、15:30。12:30 bar 是午休后 13:00–13:30 的短 bar；15:30 bar 的结束时间是 16:00。样本中该 bar 收盘价与日线收盘通常一致，但成交量经常为零，因此这个 15:30 零量不标为「零成交」。NYMEX 小时模式按 Yahoo Globex 近似时段：交易日 D 前一日 18:00 至 D 日 17:00 美东时间；日线继续使用 CSV 的 14:30 结算时刻。
